# Архитектура AI outbound-системы (2026)

## Принципы, из которых выведена архитектура

| Принцип | Опора | Уровень |
|---|---|---|
| AI сильнее всего в **исследовании и обогащении**, не в финальном тексте | Vercel: ручной ресёрч 15–25 мин на лид снят агентом, персонализацию оставили людям; Saleshandy, CaptivateIQ | C |
| Неотредактированный AI-текст проигрывает, AI-черновик + правка человека — выигрывает или равен | Pin, Prospectory, Saleshandy, Expandi, Hunter (+18% у отредактированных) — пять вендорских источников в одном направлении | B по направлению |
| C-level и переписка после первого ответа — человеку | Prospectory: C-level отвечает на AI 1,5% против 6,2%; «Hand off to humans at the first reply» | C |
| Автономный AI SDR «вместо команды» не доказан | 11x (TechCrunch 2025, C); Bridge Group: AI SDR у 1% компаний (A); Gartner: <40% продавцов увидят рост продуктивности (A) | A/C |
| Агент выдумывает при грязных и противоречивых данных | Salesforce Customer Zero: 30% «не знаю» → <10% после чистки данных | C |
| Сигналы работают при отборе: 3–5 сигналов на сегмент, порог signal-to-meeting 3–5% | Growleads, Common Room | D |
| Метрика — ответы людей и встречи, не открытия | Google не отслеживает open rate (A); трекинг связан с меньшим числом ответов (B, корреляция) | A/B |
| Нормальная инфраструктура, без warm-up-пулов и доменных сетей | Gmail sender guidelines, M3AAWG 2025–2026, Spamhaus | A |
| Дешёвые модели — механика над данными; текст, который читает человек, — сильная модель + человек | правило проекта; подтверждается данными об AI-текстах выше | D |

## Блоки: что делает, чем делать, где человек

### 1. Source data
- **Задача:** получить список компаний под ICP, а не «всех».
- **Глобально:** Apollo, Clay (сборка из многих источников), LinkedIn Sales Navigator, Crunchbase, BuiltWith.
- **Россия (проверено 15.09.2026):** открытые данные ФНС (бесплатно, коммерческое использование разрешено), ЕГРЮЛ (поштучно бесплатно, массово 150 тыс. ₽/год), API-ФНС / DaMIA / Checko (бесплатный старт, платные тарифы), Контур.Фокус API (от 96 тыс. ₽/год), СПАРК (договор); ЕИС — SOAP с токеном (FTP закрыт с 2025); каталоги Экспоцентра; рейтинги отрасли (например, Рейтинг Рунета). **Ограничения:** API hh.ru — только для целей найма и с 04.2026 закрыт без авторизации; API Поиска по организациям Яндекса запрещает сохранять данные; массовой российской базы технологий сайтов нет — нужен свой детектор; все российские ESP и «Яндекс Рассылки» запрещают отправку по собранным из открытых источников базам.
- **Свои скрипты:** XMLRiver-поиск по отраслевым запросам → домены → дедуп по ИНН/домену.
- **AI:** классификация «подходит ли компания под ICP» по тексту сайта (дешёвая модель, JSON).
- **Человек:** определяет ICP и исключения; проверяет 30–50 случайных компаний из каждого нового источника.

### 2. Company enrichment
- **Поля:** ИНН, ОКВЭД/отрасль, выручка и штат (бухотчётность ГИРБО), сайт, технологии сайта, регион, соцсети, дата последней активности.
- **Инструменты:** Clay waterfall (по заявлению Clay — покрытие ~80% против ~30% у одного провайдера, D); в РФ — API реквизитов + парсинг сайта + детектор технологий.
- **AI:** извлечение фактов из «О компании», новостей, вакансий в структурированный JSON (DeepSeek / бесплатные модели OpenRouter).
- **Человек:** выборочная проверка точности полей раз в неделю.

### 3. Contact enrichment
- **Задача:** 1–2 ЛПР на компанию (Hunter: 1–2 человека на компанию — 5,1% против 3,5%, A-вендор).
- **Инструменты:** Apollo/Hunter/Snov/Findymail; в РФ — сайт компании (страница «Команда», пресс-релизы), публичные профили, выступления на конференциях, hh.ru (контакт рекрутера — не ЛПР).
- **Правила:** не собирать адреса перебором (в США харвестинг — отягчающее обстоятельство CAN-SPAM, A); role-адреса (info@) — отдельный сегмент.
- **Человек:** подтверждает ЛПР для A-tier аккаунтов.

### 4. Signal collection
- **Сигналы и источники:** вакансии (hh.ru API, сайты вакансий), новые руководители (новости, соцсети, пресс-релизы), тендеры (zakupki.gov.ru, коммерческие агрегаторы), выставки (каталоги участников), новости и публикации (XMLRiver + Google/Яндекс News), смена технологий (детектор стека), рост штата (динамика вакансий), регуляторика (изменения 152-ФЗ/38-ФЗ, отраслевые требования), визиты сайта (только company-level и с учётом права).
- **Технически:** ежедневные задания, каждое событие — строка `signals(company_id, type, date, source_url, raw_text)`.
- **AI:** нормализация события и отсев шума (дешёвая модель).
- **Человек:** выбирает 3–5 рабочих сигналов на сегмент и пересматривает их раз в квартал (Growleads, D).

### 5. ICP & signal scoring
- **Формула (стартовая, калибруется на своих сделках):**
  `score = ICP_fit (0–10) × Σ(вес_сигнала × затухание)`; затухание сигнала 10–20% в неделю (Growleads, D); работать с верхними 20% аккаунтов (порог — 80-й перцентиль).
- **Tiers:** A (≥80-й перцентиль + ≥2 сигнала) → ABM-модель; B → стандартная цепочка; C → не писать, ждать сигнала.
- **Человек:** еженедельно смотрит, какие сигналы дали встречи; отключает сигналы с signal-to-meeting <3% (Common Room, D).

### 6. AI research
- **Задача:** 3–5 проверяемых фактов о компании с URL и датой, не старше 60–90 дней, и 1–2 гипотезы проблемы.
- **Инструменты:** веб-поиск (XMLRiver/Exa), чтение страниц, LLM с обязательными ссылками на источник.
- **Запрещено:** факты без URL, выводы о людях из личной жизни, «инсайты» без источника.
- **Человек:** проверяет факты у A-tier всегда, у B-tier выборочно (SBI: 3–5 материалов на продавца в неделю, D).

### 7. Angle selection
- **Библиотека углов** (пишет человек, 3–5 на сегмент): «вакансия → пробел в работе», «выставка → остывающие лиды», «смена платформы → потеря сценариев», «новый руководитель → аудит», «рост ассортимента → ручные рекомендации».
- **AI:** выбирает угол из библиотеки под найденные факты и ставит **relevance score** по рубрике (ниже). Новые углы AI не придумывает, только предлагает в отдельный список на ревью человеку.

### 8. Message generation
- **Модель:** сильная LLM (качество текста важнее цены), шаблон угла + факты + ограничения.
- **Ограничения:** 50–90 слов; без ссылок, картинок и вложений; один micro-CTA; без ROI-обещаний и комплиментов; запрещённые фразы; строка отказа; язык и форма обращения по стране.

### 9. Quality gate (автоматический)
| Проверка | Порог | Действие при провале |
|---|---|---|
| Факт имеет URL и дату | обязательно | в research заново |
| Свежесть факта | ≤60 дней (сигнал), ≤180 дней (контекст) | понизить tier или сменить угол |
| Relevance score (LLM-judge по рубрике) | ≥7/10 | ≥5 — сегментное письмо уровня 2; <5 — не отправлять |
| Пустые/битые поля подстановки | 0 | блок (кейс «Congrats on the .» ушёл 1 200 адресатам, E) |
| Длина | 40–110 слов | переписать |
| Запрещённые фразы и признаки питча | 0 совпадений | переписать |
| Ссылки, вложения, изображения | 0 в письме 1 | удалить |
| Юрисдикция | DE — блок; ЕС — LIA и уведомление; США — адрес и opt-out | блок/дополнить |
| Suppression и дубли | нет в suppression; нет активного треда в компании | блок |
| Лимиты ящика/домена | не превышены, рост ≤20–30%/нед | в очередь на завтра |

**Рубрика relevance score (0–10):** факт реален и проверяем (0–3) + факт свежий (0–2) + связь факта с болью, которую решает оффер (0–3) + адресат — правильная роль (0–2).

### 10. Human QA
- A-tier: 100% писем читает человек.
- B-tier: первые 2 недели нового угла — 100%, далее 20% выборочно + все письма с score 7–8.
- Человек может: править, отклонить, пометить факт как ошибочный (это сигнал для калибровки research).

### 11. Email verification & suppression
- Верификация не старше 30 дней; catch-all — отдельной малой волной; role-адреса — только если нет ЛПР.
- Не использовать SMTP-пробы против Outlook.com (Microsoft запрещает namespace mining, A).
- Глобальный suppression: отписки, «не пишите», жалобы, hard bounce, юр. запросы — навсегда, на все ящики.

### 12. Send queue
- Реальные ящики сотрудников на основном домене или поддомене (M3AAWG/Яндекс рекомендуют поддомен для отдельного потока, A).
- SPF + DKIM 2048 + DMARC (p=none → quarantine) + PTR + TLS; List-Unsubscribe + List-Unsubscribe-Post.
- Ровный темп в рабочие часы получателя, без «случайных интервалов для маскировки» (M3AAWG: имитация 1:1 — abuse).
- Без open/click tracking.
- Мониторинг: Google Postmaster Tools, SNDS/JMRP, Постмастер Mail.ru; стоп-кран при жалобах или bounce >3% в волне.

### 13. AI reply classification
- **Классы:** positive, maybe, later, send_info, wrong_person, referral, not_interested, has_vendor, price_budget, unsubscribe, ooo, bounce, auto_reply, hostile, legal_data_request.
- **Автоматически:** ooo (сдвиг шага), bounce, auto_reply, явный unsubscribe (→ suppression).
- **Правило безопасности:** слова «ФАС», «Роскомнадзор», «жалоба», «суд», «персональные данные», «откуда адрес», мат/угрозы или confidence ниже порога → класс `human_review`, никаких автоответов.
- **Контроль качества:** еженедельно 50 случайных ответов размечаются вручную; ошибки в unsubscribe/hostile = 0.

### 14. Human review
- positive/maybe/send_info/referral/objections: AI готовит черновик ответа менеджеру, человек отправляет (Vercel lead agent: approve/reject в Slack, A).
- hostile/legal: только человек, по согласованному шаблону.
- SLA: positive ≤1 рабочего часа.

### 15. CRM & tasks
- Сущности: компания, контакт, сигнал (с URL), угол, письмо (версия, score, кто проверил), ответ (класс), встреча, сделка.
- Задачи: later → на дату; referral → письмо рекомендованному; has_vendor → recycle 6–12 мес.
- Дедуп компаний (ИНН/домен) и людей; отметка смены работы.

### 16. Analytics & learning loop
- Метрики по когортам «сегмент × сигнал × угол»: human reply на контакт, positive rate, встречи на 100 контактов, opportunity, жалобы, bounce.
- Раз в 2 недели: отключать углы с positive <20% от ответов после ≥300 контактов; повышать веса сигналов, давших встречи; добавлять удачные письма в few-shot примеры генератора.
- Эксперименты — по `experiments.csv`, минимальные выборки там же (тексты тестировать только на ≥2 500 доставленных в плече; на малых объёмах — ICP/сигнал/оффер).

## Prompt architecture

Каждый шаг — отдельный вызов с JSON-выходом и явной схемой. Модель не получает задачу «напиши хорошее письмо» целиком.

| # | Промпт | Модель | Вход | Выход (JSON) |
|---|---|---|---|---|
| P1 | ICP-классификатор | дешёвая | текст сайта, ОКВЭД, штат | `{fit:0-10, reasons[], disqualifiers[]}` |
| P2 | Нормализатор сигнала | дешёвая | сырое событие | `{type, date, entity, is_relevant, why}` |
| P3 | Research-экстрактор | средняя/сильная + веб-поиск | домен, сигналы | `{facts:[{fact, url, date, confidence}], hypotheses:[{pain, based_on_fact_ids}]}` |
| P4 | Выбор угла + relevance | сильная | facts, hypotheses, библиотека углов | `{angle_id, score:{real, fresh, link_to_offer, role}, total, rationale}` |
| P5 | Генератор письма | сильная | angle.template, facts, ограничения, 3 few-shot удачных письма | `{subject, body, used_fact_ids}` |
| P6 | Критик / LLM-judge | другая сильная модель | письмо + факты + чек-лист | `{pass, violations[], rewrite_suggestion}` |
| P7 | Классификатор ответа | дешёвая | текст ответа + последнее письмо | `{class, confidence, sensitive:boolean, ooo_until}` |
| P8 | Черновик ответа | сильная | ответ, история, класс, playbook | `{draft, questions_to_ask[], crm_updates{}}` |

**P5 — пример системного промпта (сокращённо):**
```
Ты пишешь первое деловое письмо от лица {sender_name}, {sender_role} в {company}.
Цель письма — узнать, актуальна ли проблема, а не продать.
Используй ТОЛЬКО факты из списка facts (id, url). Не добавляй фактов, цифр и комплиментов от себя.
Структура: 1) факт/сигнал; 2) гипотеза проблемы, связанная с фактом; 3) одно доказательство из proof_library (если есть);
4) один мягкий вопрос-CTA из списка allowed_cta.
Ограничения: 50–90 слов; без ссылок; без слов из banned_phrases; без обещаний ROI и процентов роста;
обращение: {form_of_address}; язык: {lang}. В конце — строка отказа: {opt_out_line}.
Верни JSON {"subject": "...", "body": "...", "used_fact_ids": [...]}. Тема — 2–5 слов, без Re:/Fwd:, без эмодзи.
```

**P6 — чек-лист критика:** каждый факт в письме есть в facts и имеет URL; нет выдуманных знакомств и событий; нет комплиментов и лести; есть связь факта с проблемой; один CTA; нет питча в первых двух предложениях; длина; нет запрещённых фраз; тон соответствует роли адресата; письмо нельзя отправить другой компании без изменений (тест на шаблонность).

**P7 — правила чувствительности:** `sensitive=true`, если есть угрозы, жалобы, упоминание регуляторов/суда, вопросы о происхождении данных, эмоционально окрашенный отказ; при `sensitive=true` или `confidence<0.8` — только человек.

## Что автоматизировать, что нет

| Задача | Режим | Почему |
|---|---|---|
| Сбор компаний, enrichment, поиск контактов | автоматически + выборочная проверка | доказанная экономия времени (C) |
| ICP-классификация | автоматически + калибровка на выборке | точность публично не измерена |
| Мониторинг сигналов | обнаружение — автоматически; выбор сигналов и порогов — человек | сигналы шумят (D) |
| Скоринг | модель + правила + проверка на закрытых сделках | корреляции, самоотбор |
| Гипотезы о боли | human-in-the-loop | AI делает поверхностные выводы (C) |
| Первая строка / тело письма | AI-черновик + правка человека | неотредактированный AI проигрывает (B по направлению) |
| Письма C-level/enterprise | пишет человек, AI только ресёрч | C-level 1,5% на AI против 6,2% (C) |
| Варианты тем для тестов | AI генерирует, человек выбирает | метрика — ответы, не открытия |
| Follow-up шагов 2–3 | автоматически в рамках утверждённых шаблонов | низкий риск при лимите 3–4 шагов |
| Классификация ответов | автоматически для OOO/bounce/unsubscribe; остальное — с проверкой | нет независимых данных о точности |
| Ответ на positive/возражение | AI-черновик, человек отправляет | «Hand off to humans at the first reply» (C) |
| Переписка до встречи, торг | человек | у AI меньше обменов и хуже доходимость встреч (C) |
| Решение о масштабе рассылки, домены, лимиты | человек | риски репутации и права (A) |
| Посетители сайта из ЕС/Германии | не автоматизировать без юриста | person-level ID требует согласия (D) |

## Где AI ухудшает результат (стоп-лист)
- «Гиперперсонализация» без правки: −12% acceptance внутри тех же аккаунтов в LinkedIn (Expandi, C).
- Однообразный AI-стиль: «every AI tool sounds monotonously the same», спам-флаги AI 7,8% против 2,9% (Saleshandy, C).
- Комплименты и шаблонные поздравления → поверхностные ответы «send me some information» (Prospectory, C).
- Противоречивые данные → выдуманные ответы агента (Salesforce, C).
- Запуск по всему TAM без сигнала: «spam cannon that burns through your TAM» (Common Room, D).
