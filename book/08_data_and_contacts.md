# 8. Данные, контакты и проверка адресов

:::goals Что вы узнаете
- откуда взять 1 000 подходящих компаний без покупных баз;
- какие российские источники данных бесплатны, какие платные и где есть подводные камни;
- как найти человека, принимающего решение, и сколько контактов брать на компанию;
- как проверять адреса: верификация, catch-all, role-адреса, suppression;
- что важно знать о персональных данных и 152-ФЗ.
:::

## Почему данные — это не «купить базу»

Самый быстрый путь к базе — купить её. Самый быстрый путь к проблемам — тоже. Покупку адресов прямо запрещают или осуждают Google («Don’t purchase email addresses from other companies»), Yahoo, Mail.ru, Яндекс и отраслевая организация M3AAWG [A]. Mail.ru в правилах для отправителей пишет, что нельзя проводить рассылки «по базам адресов пользователей, которые были приобретены у третьих лиц или собраны со сторонних сайтов» [A].

Кроме запретов, есть и практическая сторона. В одном российском кейсе покупная база ЛПР за 60 тыс. ₽ дала три лида (Respondo, кейс Alter) [C]. У независимого автора, разославшего 6 583 письма, 17% не доставились (TexTerra) [C]. Старые адреса опасны ещё и потому, что Spamhaus превращает мёртвые адреса в ловушки: сначала они 12 месяцев и дольше возвращают ошибку, а потом «тихо» начинают принимать письма и фиксировать отправителей (Spamhaus) [A]. Для B2B это прямо связано со сменой работы: человек ушёл, его ящик закрыли, через год адрес стал ловушкой.

Поэтому базу нужно **собирать** под ICP и проверять перед каждой отправкой.

## Как собрать 1 000 компаний

Процесс выглядит так:

1. Собрать 2 000–3 000 кандидатов из нескольких источников.
2. Убрать дубли по ИНН или домену.
3. Классифицировать каждую компанию по тексту сайта: подходит ли под ICP (оценка 0–10). Это механическая задача — её хорошо делает недорогая языковая модель, возвращающая результат в JSON.
4. Вручную проверить 50 случайных компаний.
5. Отсечь всё с оценкой ниже 7 — останется около 1 000.

### Российские источники

Все данные ниже проверены на 15 сентября 2026 года.

**Реестр юрлиц (ЕГРЮЛ).** Выписка по одной компании на egrul.nalog.ru бесплатна. Массовый доступ платный: 150 тыс. ₽ в год за абонентское обслуживание одного реестра или 50 тыс. ₽ за однократное предоставление (ФНС) [A]. Из выписки берутся ИНН, ОКВЭД (код вида деятельности), руководитель и учредители.

**Открытые данные ФНС.** Наборы о среднесписочной численности, спецрежимах и налогах бесплатны, и ФНС прямо разрешает их коммерческое использование (nalog.gov.ru/opendata) [A]. Минус — годовой лаг: численность публикуется за прошлый год.

**«Прозрачный бизнес» ФНС.** Бесплатный веб-сервис: реестр, численность, налоги, доходы и расходы [A]. API нет, подходит для ручной проверки.

**Бухгалтерская отчётность (ГИРБО, bo.nalog.gov.ru).** По одной компании бесплатно, годовой неограниченный доступ — 200 тыс. ₽ [B]. Отсюда выручка и прибыль.

**Коммерческие API поверх данных ФНС.** API-ФНС и DaMIA дают бесплатный старт и платные тарифы от 0,1 ₽ за запрос [D]. Checko API отдаёт реестр, контакты, отчётность, госзакупки, суды и сообщения Федресурса; бесплатно около 100 запросов в сутки [D], точные цены платных тарифов проверить не удалось. Контур.Фокус API — от 96 тыс. ₽ в год за пакет до 3 000 компаний [B]. СПАРК — по договору, по оценке конкурента от 1,5 млн ₽ в год [D].

**Госзакупки (ЕИС, zakupki.gov.ru).** Бесплатно, но FTP-доступ закрыт с 1 января 2025 года; данные отдаются через SOAP-сервисы с токеном, который получают через Госуслуги [A/B]. Удобная альтернатива — раздел о контрактах в Checko API.

**Выставки.** Экспоцентр публикует интернет-каталоги участников на icatalog.expocentr.ru [A]. Единого каталога Крокус Экспо найти не удалось — списки ведут организаторы отдельных выставок.

**Вакансии.** Здесь важная ловушка. API hh.ru с апреля 2026 года отвечает ошибкой 403 на публичный запрос вакансий без авторизации [B], а условия API разрешают использовать данные только для целей найма: маркетинг и рекламные рассылки — основание для отказа в доступе (dev.hh.ru) [A]. **Для мониторинга вакансий как сигнала продаж API hh.ru использовать нельзя.** Остаются ручной мониторинг, поисковая выдача и SuperJob API (нужна регистрация приложения, максимум 500 сущностей в выдаче) [A].

**Карты и справочники.** API Поиска по организациям Яндекса стоит от 195 тыс. ₽ в год и **запрещает сохранять полученные данные** — даже бесплатная версия API Карт запрещает складывать данные «в собственную базу/excel файл» (Яндекс) [A]. У 2ГИС Places API публичного прайса нет, условия хранения данных нужно проверять отдельно.

**Технологии сайтов.** Российские детекторы CMS (iTrack, PR-CY, enterno) работают поштучно; массовой базы «сайты по технологиям» с API, как BuiltWith для западного рынка, нет [D]. Практичный путь — собственный скрипт на правилах Wappalyzer, который проверяет ваш список сайтов.

:::warning Осторожно
Контакты из каталогов выставок и справочников — это «открытые источники», которые российские сервисы рассылок прямо запрещают использовать. DashaMail называет спамом базы, «собранные из открытых источников (например, сбор почты с открытых каталогов, вроде 2Gis)», Altcraft и enKod — контакты, собранные парсингом справочников [A]. Сам по себе список компаний из каталога — нормальный источник для исследования; вопрос в том, кому и как вы потом пишете.
:::

### Глобальные источники

Для западных рынков стандартный набор — Apollo, LinkedIn Sales Navigator, Clay, Crunchbase, BuiltWith. Clay продвигает «waterfall» — последовательный запрос нескольких провайдеров данных: по заявлению Clay, один провайдер вроде ZoomInfo покрывает около 30% списка, а waterfall — около 80% [D, вендор о конкуренте].

По российскому рынку зарубежные базы покрывают ЛПР фрагментарно: обзор Trigga оценивает Apollo «не больше чем в 100 тысяч российских ЛПР» [D, заинтересованный вендор], к тому же оплата требует иностранной карты.

## Как найти человека, принимающего решение

ЛПР (лицо, принимающее решение) — тот, кто может сказать «да» или направить к тому, кто скажет.

**Сколько контактов брать.** 1–2 на компанию. Hunter видит, что кампании с 1–2 людьми на компанию получают 5,1% ответов против 3,5% при большем числе (Hunter, 2026) [C]. И никогда не пишите двум людям одной компании одновременно — это выглядит как массовая атака.

**Какая роль.** Руководитель функции, которую решает ваш продукт. В малых компаниях — основатель: у Belkins компании на 0–10 сотрудников отвечали 0,72% против 0,22% у компаний на 10 000+, а founders — 0,57% против 0,32% у VP (Belkins, 7,5 млн писем, 2026) [A]. Будьте осторожны с тем, чью работу вы предлагаете «перестроить»: в одном кейсе РОП блокировал предложение перестроить отдел продаж (Coldy, кейс AbsLead) [C].

**Где искать.** Страница «Команда» на сайте, пресс-релизы, выступления на конференциях, отраслевые СМИ, публичные профили, руководитель юрлица в реестре.

**Если ЛПР не найден.** Для средних компаний работает письмо на общий адрес с просьбой подсказать ответственного. В российских кейсах вопрос «кто у вас отвечает за…» стабильно давал максимум ответов на третьем шаге цепочки (Respondo, кейсы Nova, Completo, MyCustoms, CyberFirst) [C]. Для федеральных корпораций общий ящик не работает: в кейсе логистической компании ответы на info@ корпораций почти не приходили, а по франшизе аптек прямые ЛПР отвечали примерно втрое чаще — 3% против 1% (Coldy, кейс «Евклид») [C].

:::example Пример
Вы нашли подходящую производственную компанию на 300 сотрудников. На сайте нет страницы команды, в новостях упоминается коммерческий директор, но его email нигде не опубликован. Разумный путь: письмо на общий адрес с одной строкой — «Подскажите, пожалуйста, кто у вас отвечает за работу с дилерами? У меня есть пара конкретных наблюдений по вашей дилерской рассылке, хочу отправить их нужному человеку». Подбирать адрес директора перебором вариантов вроде ivanov@, i.ivanov@, ivan.ivanov@ не стоит: это харвестинг, который в США считается отягчающим обстоятельством по CAN-SPAM (FTC) [A], а для репутации отправителя опасен высоким bounce.
:::

## Проверка адресов

### Верификация

Верификация — проверка, существует ли адрес, до отправки. Правила:

- проверяйте адреса не раньше чем за 30 дней до отправки — база стареет;
- разделяйте результаты на **valid** (существует), **catch-all** (домен принимает любой адрес, и проверить конкретный ящик нельзя), **invalid** и **unknown**;
- valid — в основную очередь; invalid и unknown — не отправлять.

Одна техническая оговорка: Microsoft запрещает проверку адресов Outlook.com «без отправки» — так называемый namespace mining (Microsoft Policies) [A]. Выбирайте сервисы верификации, которые это учитывают.

### Catch-all и role-адреса

**Catch-all домены** Spamhaus использует как классические ловушки: адреса на доменах, принимающих любую почту, помогают ловить тех, кто рассылает по сгенерированным спискам [A]. Отправляйте на catch-all отдельной малой волной — не больше 10% дневного объёма — и останавливайтесь при росте bounce.

**Role-адреса** (info@, sales@, office@) Spamhaus относит к разновидности живых ловушек: регистрационные и ролевые адреса «почти никогда не должны быть в маркетинговом списке» [A]. Официального запрета писать на info@ у почтовиков нет. Используйте такие адреса только если ЛПР не найден и компания средняя. «Яндекс Рассылки» прямо запрещают отправку на ролевые адреса [A].

### Bounce и suppression

**Bounce** — письмо не доставлено. Hard bounce — постоянная ошибка (адреса или домена нет), soft bounce — временная (ящик переполнен, сервер ограничил скорость).

Правила почтовиков:
- ошибку 5xx не повторять, после нескольких отказов прекратить отправку на адрес (Microsoft) [A];
- автоматически отписывать адреса с несколькими bounce (Google) [A];
- остановить рассылку по адресу при ответе «пользователь не существует» (Яндекс, Mail.ru) [A];
- удалить адрес после двух bounce подряд в течение двух и более недель; временные ошибки 4xx не считать постоянными (M3AAWG) [A].

Mail.ru предупреждает, что больше 5% невалидных адресов в рассылке может привести к попаданию в спам «или даже к полной блокировке» [A]. Числового порога bounce Google и Microsoft не публикуют; AWS SES для своей платформы ставит аккаунт на проверку при bounce от 5% [A для SES]. Практический стоп-кран для cold outreach — остановить волну при bounce выше 3%.

**Suppression list** — список адресов, на которые нельзя писать никогда. Туда попадают: отписавшиеся, ответившие «не пишите», пожаловавшиеся, hard bounce, юридические запросы. Список общий для всех ящиков и кампаний и проверяется перед каждой отправкой.

**Дедупликация** — на двух уровнях: компания (ИНН или домен) и человек (email + ФИО + компания). Смена работы — новый контакт, старый уходит в архив.

## Персональные данные и 152-ФЗ

Это не юридическая консультация, а ориентиры из исследования законов (подробнее — глава 6).

- **Реквизиты юрлица не являются персональными данными.** ИНН, ОГРН, ОКВЭД, финансы из открытых данных ФНС разрешены для коммерческого использования [A].
- **ФИО и именной email руководителя — персональные данные.** Является ли email сам по себе персональными данными — спорный вопрос: Роскомнадзор считает, что да, а суды по делу А40-139096/2022 признали, что адрес без других идентификаторов — нет [B/C]. Но адрес вида ivan.petrov@company.ru или любой адрес в связке с ФИО и должностью в вашей CRM с высокой вероятностью будет персональными данными.
- **Данные из открытых источников не освобождают от обязанностей.** Если человек сам раскрыл данные без специального согласия, законность дальнейшей обработки доказывает каждый, кто их обрабатывает (152-ФЗ ст. 10.1) [A].
- **Для продвижения товаров через средства связи** 152-ФЗ ст. 15 требует предварительного согласия субъекта [A].
- **Штрафы выросли.** С 30 мая 2025 года за обработку без законного основания юрлицу грозит 150–300 тыс. ₽, за нарушение требований к согласию — 300–700 тыс. ₽ (КоАП ст. 13.11) [A].

Отдельно о контактах из соцсетей: сервисы, собирающие телефоны и email ЛПР со страниц ВКонтакте и LinkedIn, работают именно с персональными данными из соцсетей — это риск по 152-ФЗ [A].

## Чего не покупать

- **Готовые базы email и «базы ЛПР».** Запрещены или осуждаются почтовиками, дают высокий bounce и ловушки, в кейсах окупаются плохо.
- **Email appending** — дописывание email к списку по имени и компании. M3AAWG называет его «прямым нарушением ключевых ценностей» [A].
- **Дорогие enrichment-базы до проверки ICP.** Пока ICP не подтвердился на первых 300 контактах, хватит бесплатных данных ФНС, выдачи и ручной проверки.
- **Инструменты массового парсинга справочников с контактами.** Это нарушение условий большинства сервисов и прямой путь в запрещённые «открытые источники».

:::key Главное
- Базу нужно собирать под ICP, а не покупать: покупка запрещена почтовиками, а старые адреса превращаются в ловушки.
- Российский минимум: открытые данные ФНС, ЕГРЮЛ поштучно, ГИРБО, бесплатные лимиты API-ФНС и Checko, каталоги выставок, ЕИС.
- API hh.ru нельзя использовать для sales-сигналов, а данные API Поиска по организациям Яндекса нельзя сохранять.
- Берите 1–2 ЛПР на компанию и не пишите двум людям одновременно.
- Верификация не старше 30 дней; catch-all — отдельной малой волной; role-адреса — только когда нет ЛПР.
- Suppression list общий и вечный; стоп-кран волны — bounce выше 3%.
- Реквизиты юрлица — не персональные данные, ФИО и именной email — скорее всего да; законность их обработки доказываете вы.
:::

:::check Проверьте себя
1. Почему старые B2B-адреса опасны, даже если когда-то были настоящими?
2. Какие российские источники дают данные о численности и выручке бесплатно и в чём их ограничение?
3. Почему нельзя строить мониторинг вакансий для продаж на API hh.ru?
4. Сколько контактов брать на компанию и почему не стоит писать двум людям одновременно?
5. Чем catch-all адрес отличается от invalid и как с ним работать?
6. Какие адреса должны попасть в suppression list?
7. Являются ли ИНН компании и именной email руководителя персональными данными?
:::

:::practice Практика
Возьмите 30 компаний из вашего ICP. Для каждой соберите из бесплатных источников: ИНН, ОКВЭД, численность за прошлый год, выручку, сайт, одного вероятного ЛПР с источником, где вы его нашли, и один актуальный сигнал с датой и ссылкой. Отметьте, по скольким компаниям удалось найти ЛПР, а по скольким понадобится письмо «кто у вас отвечает за…».

Ожидаемый результат: таблица на 30 строк и честная оценка, сколько времени уходит на одну компанию вручную — это ориентир для решения, что автоматизировать.
:::
